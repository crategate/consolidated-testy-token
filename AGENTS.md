# AFHO (nyse-hours) — Agent Guide

SPL token protocol tied to NYSE trading hours. Market status (open / after-hours / closed / halted) drives staking incentives/penalties and an end-of-day "offer desk" that sells bonded token lots; proceeds split 80% DEX buybacks / 10% stakers / 10% dip reserve.

## Layout

- `programs/amm` — offer desk: `make_offers` (builds the daily offer sheet via the full 5-step sequential combinator; metric helpers in `instructions/helpers_make_offers.rs`), `calc_completed_offers` (scores fill % at day end), `load_test_data` (**devnet-only, remove before mainnet**), `load_offers` (**devnet-only dev tool**: posts a claimable average sheet (day_index = today), floor = 80% of live pool price; used for UI/claim dev), `dex_buyback` (working: slices the day's USDC vault into the Raydium CPMM pool while market==open — raw `invoke_signed` `swap_base_input`, no typed CPI; pseudo-random slice sizes weighted 1.9%/5% of remaining first-hour/tail → ~50% of the day's volume lands in hour 1; pacing 150 slots; unspent budget rolls over by staying in the vault; every fill ratchets `highest_buyback_basis`. Swap CPI is isolated in `execute_swap` — CPMM when the pool is pinned, mock fallback otherwise), `buy_the_dip` (always-on dip buyer, ANY market state: spends the 10% USDC dip reserve when spot falls ≥3% below the mean of the self-sampled 32-slot spot ring (sampled every 75 slots by calling the instruction; cold start <5 samples = dark). Slice = 25% of reserve × (depth/10%)² × trend mult (recent-5 minus older-15 mean of `price_changes`, ×10 gain, clamped 0.25x–1.25x); day cap 40% of day-start snapshot; pacing 150 slots; USDC leg via `execute_swap`; fills ratchet `highest_buyback_basis`), `set_keeper`, `set_cpmm_pool`/`set_sol_usdc_pool` (**authority-only** post-audit: pool pinning routes every swap, so the keeper cannot re-pin), `bounty_top_up` (permissionless two-hop AFHO→USDC→wSOL top-up of the keeper bounty). State in `state/offersState.rs`: `AmmState` (incl. `highest_buyback_basis` ratchet floor, `keeper`, `cpmm_program`/`cpmm_pool_state`/`cpmm_amm_config`, `cpmm_sol_usdc_pool`/`cpmm_sol_usdc_config`, `price_oracle`/`sol_oracle` legacy slots, `bb_*`/`dip_*` day-budget fields), `MarketMetrics` (20-day `price_changes` ring + `sample_head`, 32-slot `spot_prices` ring + `spot_head`/`spot_last_slot`, `trailing_stake_health[5]`), `AcceptedOffers` (3×[u8;5] fill %), `OfferList` + `lot_sizer` (tiers 0–22, top = 10M tokens). `Offer.remaining`/`total_offered` are **u32** (devnet-big: the old u8 cap of 255 lots collapsed large-vault sheets); `OfferList` = 104-byte zero-copy account (disc 8 + 96-byte struct) — see the load_test_data/load_offers realloc migration gotcha below. Vault topology: `afho_vault`/`usdc_vault` are ATAs of amm_state; `usdc_dip`/`usdc_rewards` are PDA token accounts (`b"amm_usdc_dip"`/`b"amm_usdc_rewards"`, amm_state signs — NOT ATAs, they'd collide with `usdc_vault`); `sol_vault`/`sol_dip`/`sol_rewards` are vestigial space-0 system PDAs (SOL legs retired — kept until the §4 state-field cleanup).
- `programs/mock-dex-pool` — **stub "DEX"** (fixed-rate AFHO dispenser; devnet/localnet only, remove before mainnet): `init_pool` (pool PDA `b"mock_pool"`+mint, token vaults are ATAs of the pool PDA), `send_afho` (out-leg CPI target for `dex_buyback`; in-leg transfer is done by the caller), `set_price` (permissionless raw-u64 `b"mock_price"` PDA — the devnet live-price stub read by `offer_claim`/`calc_completed_offers`).
- `programs/crank-oracle` — market-status PDA (`b"market_status"`). Status byte at offset 8, day index u64 at bytes 17..25. Mapping: 0=open, 1=after-hours, 2=closed, 3=halted.
- `programs/staking` — staking pool, bounty.
- `scripts/` — deployment/ops TS scripts; `scripts/oracle/` holds Switchboard feed deploy + keeper (`mev-keeper.ts` is the deployed crank: collects bounty, updates quote, fires `makeOffers` on transitions 0→1, 0→2, 3→2, fires `calcCompletedOffers` on →0, attempts `dexBuyback` slices every loop while market==open, and attempts `buyTheDip` every loop regardless of market state — those calls also keep the spot-price ring sampled).
- `sim/` — pure-stdlib Python simulation; exact ports of the 3 metrics + combiner design space (`python3 sim/run.py --quiet`), plus `sim/dip.py` + `sim/run_dip.py` (buy-the-dip trigger/sizing model that motivated the quadratic-depth + trend-slope spec).
- `app/` — Vite/React frontend; `/dash` dev dashboard route; reads `app/public/deployment.json`.
  - Effects + styling: `app/src/index.css` is an import manifest for `app/src/styles/` — `tokens.css` (palette + the `--fx-*` timing system: `--fx-base` master tick, `--fx-excite` shell excitement, `--fx-step` checkout/staking step ladders, derived `--fx-*-cycle` per-effect cycles redefined on `.app-shell`/`.amm-page-shell`), `fx-border.css` (neon border/divider flicker), `fx-shadow.css` (rainbow/conic + cornered backlit shadows — edge-only masks), `fx-text.css` (text-shadow + `GlitchText` letter/word/group span system), `glass.css` (`.glass-pane` tinted glass + `.fx-backdrop` drifting blobs), `layout.css`, `components.css`. Desk-specific effect wiring lives in `AmmPage.css` via `--fx-desk-*` cycles. Keyframes are sparse/intermittent by design — never constant blinking; `prefers-reduced-motion` strips them in `tokens.css`.

## Conventions & invariants

- **Devnet only.** `overflow-checks = true` in release — all metric math must widen before multiply (see u32 cast in `offer_accepted_aggression`).
- Units: price changes are centi-percent i16 (1% = 100); metric scores are 0–10000 (stake health 0–100); `discount_bps` u8 is tenths of a percent (115 = 11.5%). **Floor units** (live price, ratchet floor, spot ring, mock oracles) = price per whole token × 1e9 (nano-USD) — `(usdc_raw × 1e12) / afho_raw` for the 6/9-dec pair, `(usdc_raw × 1e12) / lamports` for the SOL leg. Sub-cent prices are representable ($5.2e-6 → 5,200); u64 headroom ≈ $1.8e10/token.
- Caller gates: `make_offers` / `calc_completed_offers` / `update_tradeday_stats` / `dex_buyback` / `buy_the_dip` / `distribute_staker_rewards` accept `authority || keeper`; `set_keeper` is authority-only; `set_cpmm_pool` / `set_sol_usdc_pool` are **authority-only** (post-audit: pool pinning routes every swap + claim pricing, so the hot-wallet keeper must not re-pin). Keeper-gated swap paths can only move vault funds through the pinned pool within the M3 spot band + pacing caps. Keeper defaults to authority at init, rotate via `set_keeper`.
- Metric-write separation: `make_offers` is READ-ONLY over metrics (calculate + post sheet). End-of-day metric writes (price sample, stake ratio) live in `update_tradeday_stats`, fired by the keeper BEFORE `make_offers`; start-of-day offer accounting (fill % rings) lives in `calc_completed_offers`, fired on any →0 transition. Idempotency guards: `metrics.day_index` (stats), `offer_list.day_index` (sheet), `accepted_offers.day_index` (fills).
- Offer desk rules: never offer below `highest_buyback_basis` (ratchet floor, enforced at claim time in `offer_claim`; moves up via `dex_buyback::ratchet_buyback_basis`, decays DOWN via `calc_completed_offers`: after 15 straight fill-less trading days, floor -= 2% of (floor − live price) per day, never crossing below live; `untaken_days` counter on AmmState; live price = pinned CPMM pool TWAP (vault-ratio fallback) in floor units — `price_oracle` is a legacy slot, never read); never offer more than 5% of vault per sheet; no offer sheet until ≥5 price samples (cold start = dark desk). **Closed-session boost**: whatever survives after-hours into CLOSED (state 2) prices +0.5% deeper (5 tenths, saturating) at claim time in `quote_claim`; back in extended hours (state 1 = pre-trade) remaining offers revert to the sheet's base discount. Pure function of the market state — the stored sheet is never mutated; the frontend mirrors it in `useAmmData` (`tiersDisplay`), and the announcer posts the flash-sale event on 1→2 with remaining lots (`closedSaleMessage`).
- Combinator (make_offers, sequential): 1 totals ← momentum bump-taper · 2 lot tiers ← vault abundance + excitement · 3 counts derived (50/35/15 split ÷ lot sizes; **u32, no 255 clamp**) · 4 discount ← momentum bump, aggression-tightened, strictly big>med>sml · 5 vesting ← stake health (clamped 3–25d; big tier caps at 25, sml/med saturate at 8/15), compensated for clamped discounts. **Vault-scale tier shift** (devnet-big): the lot ladder window rides the vault's magnitude — t_hat = highest tier with lot ≤ vault/100 whole tokens (1% of vault), shift = t_hat − ceiling (floor 0), so a ~750M-token vault lists tiers ≈ 13/16/19 (15k/100k/1M AFHO) with counts ≈ 374/131/18 and a sheet of ~4.9% of vault, while vaults ≤ ~900k tokens keep the original tuned ladder (shift 0 = sim/test regime). The ladder tops out at tier 22 (10M tokens): a full 1B-token vault (the supply cap) places its 1% ceiling tier exactly at the ladder top — the shift clamp never engages at any reachable vault size (t_hat ≥ 23 would need a vault ≥ 2.5B tokens). Bundles scale DOWN with the vault as it drains (same rule, monotonically lower t_hat); the nightly totals curve (momentum) drives the COUNTS, not the lot sizes. Sim/tuning: `sim/` (v3 = deployed spec) + `sim/mc_sweep.py` (Monte Carlo sweep of the exact on-chain combinator — shift ported).
- Offer constraints: sml lot tier < med < big (≥1 tier apart); discount strictly big > med > sml.
- Switchboard: Secrets feature is **deprecated** — use variableOverrides. The quote covers the market-status feed only (the JUP price feed was removed; momentum now comes from the self-sampled pool-price ring written by `update_tradeday_stats`).

## Gotchas

- **OfferList resize after upgrade (devnet-big)**: `Offer.remaining`/`total_offered` went u8 → u32, so the zero-copy `OfferList` account grew 80 → 104 bytes. A live pre-widening `offer_list` account FAILS the exact-size zero-copy load in every instruction until resized — and the load runs before account constraints, so only `migrate_offer_list` (devnet-only, authority-gated, takes the account as a raw AccountInfo and resizes in place; idempotent) can heal it. After `anchor deploy`, run `anchor run amm-test-data` (or `amm-offers`) once — both scripts call `migrate_offer_list` first. Fresh initializations (tests, new deployments) allocate the new size directly.
- **Local tests need `ANCHOR_PROVIDER_URL`**: `[provider] cluster` in Anchor.toml is `devnet` (deployment), so `anchor test`'s `AnchorProvider.env()` resolves devnet and airdrops hit the devnet faucet. Run tests against the local validator explicitly: `ANCHOR_PROVIDER_URL=http://127.0.0.1:8899 ANCHOR_WALLET=~/.config/solana/id.json yarn run ts-mocha -p ./tsconfig.json -t 1000000 tests/<file>.ts` (validator with all four programs: see the `solana-test-validator --bpf-program …` command in `tests/`' history or reuse `anchor test`'s own boot).
- Devnet: Jupiter won't index devnet mints, so any Jupiter-side sanity oracle never resolves on devnet — the desk reads the pinned CPMM pool instead, so this no longer blocks the pipeline.
- `feed-deploy.ts` writes `marketStatusFeedId` / `oracleQuoteAccount` to `app/public/deployment.json`; `amm-init.ts` consumes it.
- `dex_buyback`/`buy_the_dip` ratchet units: exec price = (input raw × 1e12) / AFHO raw, USDC-denominated on every path (the retired SOL leg once converted via `sol_oracle`; now there is only the USDC leg).
- Stack budget: `initialize_amm` blew the SBF stack until the big accounts were boxed and `opt-level = "s"` was added to `[profile.release]` — keep both; and always `anchor build` before running tests (stale .so masks fixes).
- Floor-unit price resolution: price units are integer `price_per_token × 1e9` (nano-USD, widened from ×1e3 — the old milli-USD scale truncated any price below $0.001/token to 0 and deadlocked a low-dollar LP start like $1,300 against 250M AFHO = $5.2e-6 on devnet AND mainnet). Now the minimum representable price is $1e-9. All scale factors (`FLOOR_UNITS_PER_Q32`, the vault-ratio fallback, claim cost divisor, min-out/exec-price numerators, SOL lamports) move together — keep them in sync if the scale ever changes again.
- `yarn lint` (prettier --check) fails repo-wide including at HEAD — informational only, don't reformat whole files to satisfy it.
- `crank-oracle` initializes `current_state = 99` — an intentional fail-closed sentinel outside the documented 0–3 mapping (`initialize_state` in the crank-oracle program). Every consumer guards `state <= 3`, so nothing moves until the first real oracle quote lands; do NOT clamp it to a valid state at init — a valid initial state would open gated flows before any oracle reading.
- The wSOL `mock_price` PDA is a GLOBAL raw-u64 stub (`b"mock_price"` + wSOL mint under mock-dex-pool) — it survives mint re-initializations and is the unpinned-pool fallback for every SOL price read (frontend + `offer_claim_sol`). If the desk's SOL quote is absurd (e.g. "52,000 SOL" for a 10-USDC lot), that PDA is stale at the old e3 scale; `anchor run amm-test-data` re-seeds it at 200 × 1e9. Same class of trap: pool pins (`cpmm_pool_state`, `cpmm_sol_usdc_pool`) live IN AmmState — a fresh `amm-init` drops them until `set-cpmm-pool` / `set-sol-usdc-pool` re-run.
- Before mainnet: remove `mock-dex-pool`, `load_test_data`, `load_offers`, `migrate_offer_list`, crank `test_set_state` (plus `scripts/oracle/set-oracle-state.ts` and the keeper's `--test-state` mode, the devnet-only state drivers that call it); drop the mock fallback from `execute_swap` + the vestigial `sol_*` accounts/fields (§4); rotate keeper via `set_keeper`.
- Mainnet immutability: by default every deployed program is upgradeable by the deployer keypair — there is no immutable mode until you clear it. After the final deploys pass verification (and only then: irreversible), run `solana program set-upgrade-authority <PROGRAM_ID> --final` for amm, staking, and crank_oracle (mock-dex-pool is gone by then). Sets the BPF upgrade authority to none — no future upgrades and no account close, ever; confirm with `solana program show <PID>` → `Upgrade Authority: none`. `anchor deploy` exposes no `--final` flag (the CLI `solana program deploy --final` does, for fresh deploys), so this is a separate finalization step. It freezes code only — program-owned state (keeper via `set_keeper`, pool pins, day budgets) still moves through the program's own authority/keeper paths.
- Staking tests live at `tests/staking.test.ts` (the old `programs/staking/tests/test_staking.ts` is gone); vault accounts in `stake`/`claim`/`unstake`/`deposit_rewards` are address-pinned to the pool's vaults (post-audit).
- Root `tsc` shows pre-existing errors from `app/` — check script files individually instead.
