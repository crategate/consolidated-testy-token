# AFHO (nyse-hours) — Agent Guide

SPL token protocol tied to NYSE trading hours. Market status (open / after-hours / closed / halted) drives staking incentives/penalties and an end-of-day "offer desk" that sells bonded token lots; proceeds split 80% DEX buybacks / 10% stakers / 10% dip reserve.

## Layout

- `programs/amm` — offer desk: `make_offers` (builds the daily offer sheet via the full 5-step sequential combinator; metric helpers in `instructions/helpers_make_offers.rs`), `calc_completed_offers` (scores fill % at day end), `load_test_data` (**devnet-only, remove before mainnet**), `load_offers` (**devnet-only dev tool**: posts a claimable average sheet (day_index = today), floor = 80% of live pool price; used for UI/claim dev), `dex_buyback` (working: slices the day's USDC vault into the Raydium CPMM pool while market==open — raw `invoke_signed` `swap_base_input`, no typed CPI; pseudo-random slice sizes weighted 1.5%/5% of remaining first-hour/tail → ~50% of the day's volume lands in hour 1; pacing 150 slots; unspent budget rolls over by staying in the vault; every fill ratchets `highest_buyback_basis`. Swap CPI is isolated in `execute_swap` — **Raydium CPMM ONLY; the mock-dex-pool venue is deleted** and every swap/pricing instruction hard-errors with `PoolNotPinned` until `set_cpmm_pool` runs), `buy_the_dip` (always-on dip buyer, ANY market state: spends the 10% USDC dip reserve when spot falls ≥3% below the mean of the self-sampled 32-slot spot ring (sampled every 75 slots by calling the instruction; cold start <5 samples = dark). Slice = 25% of reserve × (depth/10%)² × trend mult (recent-5 minus older-15 mean of `price_changes`, ×10 gain, clamped 0.25x–1.25x); day cap 40% of day-start snapshot; pacing 150 slots; USDC leg via `execute_swap`; fills ratchet `highest_buyback_basis`), `set_keeper`, `set_cpmm_pool`/`set_sol_usdc_pool` (**authority-only** post-audit: pool pinning routes every swap, so the keeper cannot re-pin), `bounty_top_up` (permissionless two-hop AFHO→USDC→wSOL top-up of the keeper bounty). State in `state/offersState.rs`: `AmmState` (incl. `highest_buyback_basis` ratchet floor, `keeper`, `cpmm_program`/`cpmm_pool_state`/`cpmm_amm_config`, `cpmm_sol_usdc_pool`/`cpmm_sol_usdc_config`, `price_oracle`/`sol_oracle` legacy slots, `bb_*`/`dip_*` day-budget fields), `MarketMetrics` (20-day `price_changes` ring + `sample_head`, 32-slot `spot_prices` ring + `spot_head`/`spot_last_slot`, `trailing_stake_health[5]`), `AcceptedOffers` (3×[u8;5] fill %), `OfferList` + `lot_sizer` (tiers 0–22, top = 10M tokens). `Offer.remaining`/`total_offered` are **u32** (devnet-big: the old u8 cap of 255 lots collapsed large-vault sheets); `OfferList` = 104-byte zero-copy account (disc 8 + 96-byte struct) — see the load_test_data/load_offers realloc migration gotcha below. Vault topology: `afho_vault`/`usdc_vault` are ATAs of amm_state; `usdc_dip`/`usdc_rewards` are PDA token accounts (`b"amm_usdc_dip"`/`b"amm_usdc_rewards"`, amm_state signs — NOT ATAs, they'd collide with `usdc_vault`); `sol_vault`/`sol_dip`/`sol_rewards` are vestigial space-0 system PDAs (SOL legs retired — kept until the §4 state-field cleanup).
- `programs/crank-oracle` — market-status PDA (`b"market_status"`). Status byte at offset 8, day index u64 at bytes 17..25. Mapping: 0=open, 1=after-hours, 2=closed, 3=halted.
- `programs/staking` — staking pool, bounty.
- `scripts/` — deployment/ops TS scripts; `scripts/oracle/` holds Switchboard feed deploy + keeper (`mev-keeper.ts` is the deployed crank: collects bounty, updates quote, fires `makeOffers` on transitions 0→1, 0→2, 3→2, fires `calcCompletedOffers` on →0, attempts `dexBuyback` slices every loop while market==open, and attempts `buyTheDip` every loop regardless of market state — those calls also keep the spot-price ring sampled).
- `sim/` — pure-stdlib Python simulation; exact ports of the 3 metrics + combiner design space (`python3 sim/run.py --quiet`), plus `sim/dip.py` + `sim/run_dip.py` (buy-the-dip trigger/sizing model that motivated the quadratic-depth + trend-slope spec).
- `app/` — Vite/React frontend; `/dash` dev dashboard route; reads `app/public/deployment.json`.
  - Effects + styling: `app/src/index.css` is an import manifest for `app/src/styles/` — `tokens.css` (palette + the `--fx-*` timing system: `--fx-base` master tick, `--fx-excite` shell excitement, `--fx-step` checkout/staking step ladders, derived `--fx-*-cycle` per-effect cycles redefined on `.app-shell`/`.amm-page-shell`), `fx-border.css` (neon border/divider flicker), `fx-shadow.css` (rainbow/conic + cornered backlit shadows — edge-only masks), `fx-text.css` (text-shadow + `GlitchText` letter/word/group span system), `glass.css` (`.glass-pane` tinted glass + `.fx-backdrop` drifting blobs), `layout.css`, `components.css`. Desk-specific effect wiring lives in `AmmPage.css` via `--fx-desk-*` cycles. Keyframes are sparse/intermittent by design — never constant blinking; `prefers-reduced-motion` strips them in `tokens.css`.

## Commands

- Build/check: `anchor build`; `cargo check -p amm` (fast iteration; ignore anchor macro `cfg` warnings)
- Tests: `yarn test` (all), `yarn test-staking`; `tests/buy-the-dip.test.ts` + `tests/dex-buyback.test.ts` + `tests/offer-claim.test.ts` + `tests/ratchet-decay.test.ts` run against a local validator (`solana-test-validator --bpf-program …` for all 4 programs) — cover dip-buy cold-start/trigger/depth/throttle/pacing/SOL-leg/auth, buyback gating/weighting/pacing/rollover/ratchet, claim splits/vesting/gating, and floor-decay grace/convergence/reset/guards. `load_test_data` knobs: metrics rings (incl. `spot_prices`/`spot_head`), fill %, `buyback_basis`, `untaken_days`, offer-sheet totals (**u32 counts** + tier terms).
- Ops (via `anchor run …`): `mint` → `init` → `feed-deploy` → `amm-init` → `amm-test-data` → `bount` (keeper). PDAs from earlier steps are inputs to later ones — order matters. **After every fresh `amm-init`, run `set-pools`** (one-shot: `set-cpmm-pool` + `set-sol-usdc-pool` + `create-claim-alt`) — the pool pins live IN AmmState and a fresh state has none; every swap/pricing instruction hard-errors (`PoolNotPinned`) until they land, so the staker 10% never leaves `usdc_rewards` and no buyback slices fire. The three steps also exist standalone (`set-cpmm-pool`, `set-sol-usdc-pool`, `create-claim-alt`) for partial re-runs; `create-claim-alt` is a no-op unless a pin CHANGED an address (ALTs are append-only).
- Lint: `yarn lint`

## Conventions & invariants

- **Devnet only.** `overflow-checks = true` in release — all metric math must widen before multiply (see u32 cast in `offer_accepted_aggression`).
- Units: price changes are centi-percent i16 (1% = 100); metric scores are 0–10000 (stake health 0–100); `discount_bps` u8 is tenths of a percent (115 = 11.5%). **Floor units** (live price, ratchet floor, spot ring, mock oracles) = price per whole token × 1e9 (nano-USD) — `(usdc_raw × 1e12) / afho_raw` for the 6/9-dec pair, `(usdc_raw × 1e12) / lamports` for the SOL leg. Sub-cent prices are representable ($5.2e-6 → 5,200); u64 headroom ≈ $1.8e10/token.
- Caller gates: `make_offers` / `calc_completed_offers` / `update_tradeday_stats` / `dex_buyback` / `buy_the_dip` / `distribute_staker_rewards` accept `authority || keeper`; `set_keeper` is authority-only; `set_cpmm_pool` / `set_sol_usdc_pool` are **authority-only** (post-audit: pool pinning routes every swap + claim pricing, so the hot-wallet keeper must not re-pin). Keeper-gated swap paths can only move vault funds through the pinned pool within the M3 spot band + pacing caps. Keeper defaults to authority at init, rotate via `set_keeper`.
- Metric-write separation: `make_offers` is READ-ONLY over metrics (calculate + post sheet). End-of-day metric writes (price sample, stake ratio) live in `update_tradeday_stats`, fired by the keeper BEFORE `make_offers`; start-of-day offer accounting (fill % rings) lives in `calc_completed_offers`, fired on any →0 transition. Idempotency guards: `metrics.day_index` (stats), `offer_list.day_index` (sheet), `accepted_offers.day_index` (fills).
- Offer desk rules: never offer below `highest_buyback_basis` (ratchet floor, enforced at claim time in `offer_claim`; moves up via `dex_buyback::ratchet_buyback_basis`, decays DOWN via `calc_completed_offers` (fill-modulated, depth-accelerated — 2026-09-04): it runs on every LOCKED trading day (live < floor) after a 3-locked-day grace, cut = 2% of the gap × depth factor (×1 at ≤10% gap up to ×8 at ≥70%) × demand keep (tier-weighted fill % of the scored sheet, big×4/med×2/sml×1 — a cleared sheet holds the floor, a ~$0.05 pity lot decays at ~full rate; fills can slow decay but never block it); `untaken_days` counts consecutive locked days and resets only on price recovery (live ≥ floor) — the old any-fill reset let a single small claim stall the desk forever; live price = pinned CPMM pool TWAP (vault-ratio fallback) in floor units — `price_oracle` is a legacy slot, never read); never offer more than 5% of vault per sheet; no offer sheet until ≥5 price samples (cold start = dark desk). **Closed-session boost**: whatever survives after-hours into CLOSED (state 2) prices +0.5% deeper (5 tenths, saturating) at claim time in `quote_claim`; back in extended hours (state 1 = pre-trade) remaining offers revert to the sheet's base discount. Pure function of the market state — the stored sheet is never mutated; the frontend mirrors it in `useAmmData` (`tiersDisplay`), and the announcer posts the flash-sale event on 1→2 with remaining lots (`closedSaleMessage`).
- Combinator (make_offers, sequential): 1 totals ← momentum bump-taper · 2 lot tiers ← vault abundance + excitement · 3 counts derived (50/35/15 split ÷ lot sizes; **u32, no 255 clamp**) · 4 discount ← momentum bump, aggression-tightened, strictly big>med>sml · 5 vesting ← stake health (clamped 3–25d; big tier caps at 25, sml/med saturate at 8/15), compensated for clamped discounts. **Vault-scale tier shift** (devnet-big): the lot ladder window rides the vault's magnitude — t_hat = highest tier with lot ≤ vault/100 whole tokens (1% of vault), shift = t_hat − ceiling (floor 0), so a ~750M-token vault lists tiers ≈ 13/16/19 (15k/100k/1M AFHO) with counts ≈ 374/131/18 and a sheet of ~4.9% of vault, while vaults ≤ ~900k tokens keep the original tuned ladder (shift 0 = sim/test regime). The ladder tops out at tier 22 (10M tokens): a full 1B-token vault (the supply cap) places its 1% ceiling tier exactly at the ladder top — the shift clamp never engages at any reachable vault size (t_hat ≥ 23 would need a vault ≥ 2.5B tokens). Bundles scale DOWN with the vault as it drains (same rule, monotonically lower t_hat); the nightly totals curve (momentum) drives the COUNTS, not the lot sizes. Sim/tuning: `sim/` (v3 = deployed spec) + `sim/mc_sweep.py` (Monte Carlo sweep of the exact on-chain combinator — shift ported).
- Offer constraints: sml lot tier < med < big (≥1 tier apart); discount strictly big > med > sml.
- **Above-spot gate (UI)**: when the ratchet floor holds a selected tier's effective price at/above the live pool price, the desk's buy button blocks (`Floor held — not below spot`) with an explanatory order note. Deliberately UI-only — the on-chain floor stays the protocol invariant and a CLI buyer can still transact. Rationale: a spot-priced, vesting-locked bond is strictly dominated by the open market, and fills SLOW the floor's decay (demand keep in `calc_completed_offers`), so gating above-spot sales accelerates the return to real discounts. Partial-ratchet tiers (floor > discounted but still < spot) stay buyable, flagged `floor held` / `at spot` on the card. While the closed-session bonus is live the card's price/lot renders in the bonus blue (the math already includes it — the color makes it visible).
- **SOL payment leg (offer_claim_sol)** — bonds stay purchasable in SOL (only the protocol's internal vault flows are USDC-only): the buyer's lamports are solved from the pinned SOL/USDC pool's live vault balances (`cpmm_swap_input_for_out`, 25bps input-leg fee; `sol_price` is a fail-closed sanity read) — note Raydium's curve itself trades against vault-minus-fee-ledger reserves, so the vault-based charge is mildly conservative when fees have accrued. The charge = spot + the trade's own price impact, and the protocol always nets the full USDC cost. The desk mirrors that exact solve client-side (`lamportsForCostExact` over `computeLivePrice`'s `solPoolReserves`, same raw vault amounts) instead of the spot ratio, and shows "SOL pool too thin" / blocks the buy when the order cost ≥ the pool's USDC vault (the on-chain `InsufficientPoolLiquidity` revert). Devnet gotcha: that pinned pool is small and the desk's own flows move it — `bounty_top_up` drains wSOL (price up), SOL claims drain USDC (price down + impact) — so its implied SOL price drifts unanchored (observed 200 → ~2,290 USDCoct/SOL, which priced every SOL bond ~10× low). Re-anchor with `anchor run rebalance-sol-pool` (dry-run by default, `EXECUTE=1` to send; `SOL_POOL_TARGET_USDC_PER_SOL` overrides the 200 default). Creator fee is disabled on the pinned config (`feeOn = 0` / `enableCreatorFee = false`) — if a future config enables it, both the on-chain 25bps solve and the rebalance fee model need revisiting. **This drift is live and fast, not theoretical** (2026-09-05 pool history): the rebalance landed 197.0 USDCoct/SOL and a bounty top-up 32s later moved it to 406; five top-ups in 44 min took it 104 → 2,859. Charges were correct at each instant (claims filled at 207/185/168), but the desk's polled display lags the pool between polls — the fix is a deeper devnet pool (re-run `set-sol-usdc-pool` with `SOL_USDC_SEED_SOL`/`SOL_USDC_SEED_USDC` sized for real flow) and re-pinning, not more rebalances.
- **SOL claim transaction: v0 + ALT required** — the legacy SOL claim tx is ~1213 bytes (19 under the packet limit), so it cannot carry a compute-budget instruction and runs on the 200k CU default while consuming 141–166k (Raydium CPI + staking CPI); wallet simulations sit right at that edge and fail (`ComputationalBudgetExceeded` under the wallet's own sim, then the manual "allow again" lands it). `scripts/create-claim-alt.ts` (or `anchor run set-pools`) creates/extends the claim lookup table (29 static accounts) and writes `claimLookupTable` into deployment.json; `useOfferClaim` then sends the claim as a v0 transaction with `setComputeUnitLimit(400_000)` and falls back to the legacy form when the table is missing/incomplete. Re-run after a pool pin CHANGES an address (append-only table).
- Switchboard: Secrets feature is **deprecated** — use variableOverrides. The quote covers the market-status feed only (the JUP price feed was removed; momentum now comes from the self-sampled pool-price ring written by `update_tradeday_stats`).

## Gotchas

- **OfferList resize after upgrade (devnet-big)**: `Offer.remaining`/`total_offered` went u8 → u32, so the zero-copy `OfferList` account grew 80 → 104 bytes. A live pre-widening `offer_list` account FAILS the exact-size zero-copy load in every instruction until resized — and the load runs before account constraints, so only `migrate_offer_list` (devnet-only, authority-gated, takes the account as a raw AccountInfo and resizes in place; idempotent) can heal it. After `anchor deploy`, run `anchor run amm-test-data` (or `amm-offers`) once — both scripts call `migrate_offer_list` first. Fresh initializations (tests, new deployments) allocate the new size directly.
- **Local tests need `ANCHOR_PROVIDER_URL`**: `[provider] cluster` in Anchor.toml is `devnet` (deployment), so `anchor test`'s `AnchorProvider.env()` resolves devnet and airdrops hit the devnet faucet. Run tests against the local validator explicitly: `ANCHOR_PROVIDER_URL=http://127.0.0.1:8899 ANCHOR_WALLET=~/.config/solana/id.json yarn run ts-mocha -p ./tsconfig.json -t 1000000 tests/<file>.ts` (validator with all four programs: see the `solana-test-validator --bpf-program …` command in `tests/`' history or reuse `anchor test`'s own boot).
- Devnet: Jupiter won't index devnet mints, so any Jupiter-side sanity oracle never resolves on devnet — the desk reads the pinned CPMM pool instead, so this no longer blocks the pipeline.
- `feed-deploy.ts` writes `marketStatusFeedId` / `oracleQuoteAccount` to `app/public/deployment.json`; `amm-init.ts` consumes it.
- `dex_buyback`/`buy_the_dip` ratchet units: exec price = (input raw × 1e12) / AFHO raw, USDC-denominated on every path (the retired SOL leg once converted via `sol_oracle`; now there is only the USDC leg).
- Stack budget: `initialize_amm` blew the SBF stack until the big accounts were boxed and `opt-level = "s"` was added to `[profile.release]` — keep both; and always `anchor build` before running tests (stale .so masks fixes).
- Floor-unit price resolution: price units are integer `price_per_token × 1e9` (nano-USD, widened from ×1e3 — the old milli-USD scale truncated any price below $0.001/token to 0 and deadlocked a low-dollar LP start like $1,300 against 250M AFHO = $5.2e-6 on devnet AND mainnet). Now the minimum representable price is $1e-9. All scale factors (`FLOOR_UNITS_PER_Q32`, the vault-ratio fallback, claim cost divisor, min-out/exec-price numerators, SOL lamports) move together — keep them in sync if the scale ever changes again. `FLOOR_UNITS_PER_Q32 = 1e12` specifically (must equal the vault-ratio ×1e12 numerator for the 6/9-dec pools; a same-decimals pair would need 1e9). The TWAP conversion scales BEFORE dividing by dt/Q32 so sub-penny tokens keep precision — the pre-fix 1e9 returned floor 2 vs 2500 on a fresh observation ring (inverted mint order) and failed every swap CPI with Raydium 0x1775 `ExceededSlippage` (intermittent: only within 600s of the last pool trade; older rings fell back to the vault ratio and worked).
- SOL/USDC pool pin must contain the AMM's OWN USDC mint (`USDCoct…` on devnet): pinning Raydium's real-devnet-USDC pool (`4zMMC…`, e.g. `GoZmdd…`) silently breaks the frontend SOL price (vault derived with the wrong mint → "—"), `offer_claim_sol`, and `bounty_top_up`. Prefer `set-sol-usdc-pool`'s find-or-create path over hand-copying a pool address into deployment.json.
- `yarn lint` (prettier --check) fails repo-wide including at HEAD — informational only, don't reformat whole files to satisfy it.
- `crank-oracle` initializes `current_state = 99` — an intentional fail-closed sentinel outside the documented 0–3 mapping (`initialize_state` in the crank-oracle program). Every consumer guards `state <= 3`, so nothing moves until the first real oracle quote lands; do NOT clamp it to a valid state at init — a valid initial state would open gated flows before any oracle reading.
- The wSOL `mock_price` PDA and the whole mock-dex-pool program are DELETED (2026-09-03). Pricing is pool-only everywhere: the AFHO price comes from the pinned AFHO/USDC CPMM (TWAP, vault-ratio fallback), the SOL price from the pinned SOL/USDC CPMM. Until a pool is pinned the desk shows "—" / disables the affected flows (fail closed); on-chain instructions return `PoolNotPinned`. Same class of trap: pool pins (`cpmm_pool_state`, `cpmm_sol_usdc_pool`) live IN AmmState — a fresh `amm-init` drops them until `set-cpmm-pool` / `set-sol-usdc-pool` re-run.
- Before mainnet: ~~remove `mock-dex-pool`~~ (DONE 2026-09-03 — program deleted, `execute_swap`/pricing are CPMM-only, mock accounts stripped from every instruction, localnet mock tests moved to `tests/legacy-mock/` pending CPMM-based rewrite), remove `load_test_data`, `load_offers`, `migrate_offer_list`, crank `test_set_state` (plus `scripts/oracle/set-oracle-state.ts` and the keeper's `--test-state` mode, the devnet-only state drivers that call it); remove the dead `AmmState` legacy fields (`price_oracle`/`spot_oracle`/`sol_oracle`/`dex_program`/`sol_vault`/`sol_dip`/`sol_rewards` + sol budget counters — unread since the mock removal, §4); rotate keeper via `set_keeper`.
- **Slot-time assumption**: all slot-denominated pacing (dex_buyback `MIN_SLICE_SLOTS`, buy_the_dip `DIP_MIN_SLICE_SLOTS`/`SPOT_SAMPLE_SLOTS`) derives at compile time from `NOMINAL_SLOT_MS` (400ms, defined in `dex_buyback.rs`, mirrored in `mev-keeper.ts`). A ~200ms mainnet slot target is ATTEMPTED (Alpenglow-class consensus change), not guaranteed — if it ever lands, flip that ONE constant (→ 300/300/150; pacing stays ~1 slice/min, ~30s sampling) and redeploy **before** `solana program set-upgrade-authority --final` — a finalized program can never be re-tuned. Wall-clock windows (1h first-hour gate, 600s TWAP, day caps) need nothing. The keeper logs measured ms/slot (`getRecentPerformanceSamples`) vs the assumption every ~5 min.
- Mainnet immutability: by default every deployed program is upgradeable by the deployer keypair — there is no immutable mode until you clear it. After the final deploys pass verification (and only then: irreversible), run `solana program set-upgrade-authority <PROGRAM_ID> --final` for amm, staking, and crank_oracle (mock-dex-pool is gone by then). Sets the BPF upgrade authority to none — no future upgrades and no account close, ever; confirm with `solana program show <PID>` → `Upgrade Authority: none`. `anchor deploy` exposes no `--final` flag (the CLI `solana program deploy --final` does, for fresh deploys), so this is a separate finalization step. It freezes code only — program-owned state (keeper via `set_keeper`, pool pins, day budgets) still moves through the program's own authority/keeper paths.
- Staking tests live at `tests/staking.test.ts` (the old `programs/staking/tests/test_staking.ts` is gone); vault accounts in `stake`/`claim`/`unstake`/`deposit_rewards` are address-pinned to the pool's vaults (post-audit).
- Root `tsc` shows pre-existing errors from `app/` — check script files individually instead.
